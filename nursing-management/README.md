# מערכת ניהול סיעוד — גרסה 3

מערכת לניהול נתוני כוח האדם של הנהלת הסיעוד: עובדים, בטיחות הטיפול, אחראיות משמרת, שיחות משוב, הערכות, חת"ש והרשאות, תקן ותנועות כוח אדם.

* **מדריך למשתמש:** `docs/הנחיות_עבודה.docx` — התקנה, ניסיון ראשון, סיסמאות, הרשאות ועבודה יומיומית.
* **קובץ אחד, ללא התקנה** — `dist/מערכת_ניהול_סיעוד.html`. נפתח ב-Google Chrome או Microsoft Edge.
* **מאגר נתונים אחד ואמין** — כל המשתמשים עובדים על אותו קובץ נתונים בתיקיית הרשת.
* **דוחות בדיוק במבנה קובץ הנהלת הסיעוד** — אותם גיליונות, כותרות, גופנים, צבעים, מסגרות, תאים ממוזגים, רוחבי עמודות ונוסחאות.

---

## התקנה (פעם אחת)

1. יוצרים תיקייה ברשת, למשל `\\server\nursing\מערכת ניהול סיעוד`.
2. מעתיקים אליה את הקובץ `מערכת_ניהול_סיעוד.html`.
3. פותחים את הקובץ ב-Chrome או ב-Edge (לחיצה כפולה, או גרירה לחלון הדפדפן).
4. במסך הפתיחה: **"בחירת התיקייה המשותפת"** ובוחרים את אותה תיקייה (זו שבה נמצא הקובץ).
5. מקימים את חשבון **הנהלת הסיעוד** (מנהל/ת המערכת).
6. **ייבוא מקבצים** ← גוררים את קובץ האקסל של הנהלת הסיעוד ← בודקים את רשימת השינויים ← "ביצוע הייבוא".

### מחשב נוסף / משתמש נוסף
פותחים את אותו קובץ מהרשת ← "בחירת התיקייה המשותפת" ← נכנסים עם שם המשתמש שהוקם עבורכם.
הדפדפן זוכר את התיקייה. בפתיחות הבאות לפעמים יופיע כפתור **"אישור גישה"** — לחיצה אחת מספיקה (זו דרישת אבטחה של הדפדפן).

> מומלץ לאשר בדפדפן "לאפשר בכל ביקור" כשמופיעה בקשת הגישה לתיקייה.

## שדרוג מהגרסה הקודמת

1. מחליפים **רק** את קובץ ה-HTML בתיקייה בקובץ החדש (באותו שם).
2. בפתיחה הראשונה המערכת מזהה את `data/application-data.json` של הגרסה הקודמת ומעבירה ממנו אוטומטית את המחלקות, העובדים, הנתונים, תנועות כוח האדם **והמשתמשים — עם הסיסמאות הקיימות**.
3. הקובץ הישן נשאר בתיקייה ללא שינוי (כגיבוי).

יש לעדכן את הקובץ בכל המחשבים: הגרסה החדשה שומרת את הנתונים בקובץ חדש (`data/nursing-db.json`).

## מבנה התיקייה המשותפת

```
מערכת_ניהול_סיעוד.html   ← המערכת
data/nursing-db.json      ← מאגר הנתונים היחיד (כל המשתמשים)
data/presence/            ← מי מחובר כרגע
backups/                  ← גיבוי אוטומטי יומי (60 יום) + לפני כל ייבוא/שחזור + גיבויים ידניים
documents/<עובד>/          ← מסמכים סרוקים של עובדים
reports/<תאריך>/           ← עותק של כל דוח שהופק
```

## סנכרון בין מחשבים

* כל שינוי נשמר אוטומטית תוך פחות משנייה, ומופיע אצל שאר המשתמשים תוך כמה שניות.
* שני משתמשים שעורכים **עובדים שונים או שדות שונים** באותו זמן — שני השינויים נשמרים.
* אם שני משתמשים שינו **את אותו שדה ממש** באותו זמן — נשמר הערך של מי ששמר אחרון, וזה נרשם ביומן ("התנגשות עריכה").
* אם הרשת מתנתקת — אפשר להמשיך לעבוד. השינויים נשמרים במחשב ומסונכרנים כשהרשת חוזרת.
* מחיקה מול עריכה במקביל: הרשומה נשמרת (לא מאבדים מידע).

## משתמשים והרשאות

* **מנהל/ת מערכת** — גישה מלאה, כולל משתמשים, הגדרות וגיבויים.
* **עריכה שוטפת** — עובדים, גיליונות, תנועות, מסמכים, הפקת דוחות.
* **צפייה בלבד**.
* **מותאם אישית** — טבלת הרשאות לפי אזור (צפייה / עריכה / פעולה).
* **הגבלה למחלקות** — למשל אחראית מחלקה רואה ומעדכנת רק את עובדי המחלקה שלה.

סיסמאות נשמרות כ-hash בלבד (PBKDF2-SHA256). 5 ניסיונות כושלים נועלים את החשבון ל-10 דקות. המסך ננעל אחרי 30 דקות ללא פעילות.
איפוס סיסמה יוצר סיסמה זמנית, והמשתמש נדרש לבחור סיסמה אישית בכניסה הבאה. אי אפשר למחוק או להשבית את מנהל המערכת הפעיל האחרון.

> **אין יציאת מידע מהמחשב:** המערכת לא מכילה קוד שפונה לרשת. בנוסף, בראש הקובץ יש הגדרת אבטחה (Content-Security-Policy) שגורמת לדפדפן לחסום כל חיבור יוצא מהדף — גם אם מישהו ינסה להוסיף כזה. הבדיקה `tests/security-check.js` מנסה לשלוח מידע החוצה בכל הדרכים (fetch, XHR, WebSocket, תמונה, סקריפט, iframe, beacon) ומוודאת שכולן נחסמות.
> המידע נשמר רק: בתיקיית הרשת שנבחרה, בעותק מקומי בדפדפן של כל מחשב שבו נכנסו (לעבודה בניתוק רשת), ובקבצי דוחות שמורידים למחשב.

> **אבטחת הקבצים עצמם:** אין שרת, לכן ההגנה על הקבצים בתיקייה נקבעת בהרשאות Windows של התיקייה. מומלץ לתת גישה לתיקייה רק לצוות המורשה.

## מסכי העבודה

| מסך | מה עושים בו |
|---|---|
| לוח בקרה | מדדים לכל מחלקה, ורשימת "דורש טיפול": מינוי אחראי משמרת שפג או יפוג, הרשאת מתן דם, בדיקות ושיחות חסרות |
| עובדים | חיפוש וסינון, כרטיס עובד מלא בלשוניות, הוספת עובד, סיום העסקה (נרשם אוטומטית ב"הפסקת עבודה") |
| גיליונות הנהלת הסיעוד | עריכה ישירה בטבלה במבנה כל גיליון (Enter ↓, Tab ←, רווח = ✓). צבעים: ירוק בוצע, כתום יפוג בקרוב, אדום פג תוקף |
| נכנסים ועוזבים | גיליון "תקינה" לפי תקופה |
| תקן מקוצר | דרישות, משמרות מאושרות ותקנים. "תקנים בפועל" מחושב אוטומטית מחלקיות המשרה של העובדים |
| הפקת דוחות | בחירת מחלקות וגיליונות ← קובץ Excel, או תצוגה מקדימה והדפסה/PDF באותו מבנה |
| ייבוא מקבצים | קובץ האקסל של הנהלת הסיעוד (כל הגיליונות), או קובץ נתונים מהגרסה הקודמת |

### ייבוא — מה נבדק
* השורות של כל עובד/ת בכל הגיליונות מאוחדות לפי **ת.ז.**, ובגיליון ללא ת.ז. (שיחות עובדים) לפי שם. ההתאמה עובדת גם כשסדר השם הפוך או יש הבדלי כתיב קטנים.
* **מספרי ת.ז. סותרים** בין גיליונות, והתאמות שם לא ודאיות, מסומנים "לבדיקה".
* לפני הביצוע מוצגת רשימת השינויים (מה היה ← מה יהיה) לכל עובד/ת, ואפשר לבטל סימון של פריטים.
* תא ריק בקובץ **לא מוחק** מידע קיים. לפני כל ייבוא נשמר גיבוי.

## התאמות בדוח לעומת קובץ המקור

הדוח נבנה מתבנית שחולצה מקובץ הנהלת הסיעוד (`assets/report-template.json`, ללא נתונים אישיים). ההבדלים המכוונים:
* **תקן מקוצר:** נוספה שורה "א. מוסמכות". בקובץ המקור הנוסחאות (`SUM(D4:D5)`) מצביעות על שורה כזו, אבל השורה עצמה חסרה.
* **תקן ← סטודנטים:** שורת הסיכום נקראת "סה"כ סטודנטים". בקובץ המקור כתוב בטעות "סה"כ כוחות עזר".
* חישוב היחס משתמש ב-`IFERROR`, כדי שלא יופיע `#DIV/0!` כשאין נתונים.
* הגדרות הדפסה: לרוחב, בהתאמה לרוחב עמוד.
* מספר עמודות השנים (בטיחות, שיחות, הערכות) נקבע בהגדרות.

## פיתוח

```
npm install            # ExcelJS לבדיקות (בקובץ הסופי הספרייה מוטמעת)
npm run build          # בונה את dist/מערכת_ניהול_סיעוד.html
npm test               # בדיקות ליבה: ייבוא, ייצוא, סבב הלוך-חזור, מיזוג, סיסמאות, מעבר גרסה
node tests/e2e.js <קובץ.xlsx> <תיקיית-עבודה>   # בדיקת דפדפן: שני מחשבים על תיקייה משותפת (Playwright)
node tests/e2e-upgrade.js <תיקיית-עבודה>       # בדיקת שדרוג מהגרסה הקודמת
python3 tools/extract_template.py <קובץ-מקור.xlsx>   # עדכון תבנית הדוח מקובץ אקסל מעודכן
node tools/make_guide.js docs/הנחיות_עבודה.docx   # יצירת מסמך ההנחיות למשתמש
```

מבנה הקוד (`src/js`): `00-util` · `10-model` (מודל הנתונים, התראות, הרשאות, מעבר גרסה) · `20-merge` (מיזוג תלת-כיווני) · `30-import` · `40-export` · `45-auth` · `50-store` (תיקייה משותפת, נעילה, סנכרון, גיבויים) · `60…67` מסכים · `99-main`.
ExcelJS 4.4.0 (רישיון MIT) מוטמעת בקובץ, כך שהמערכת עובדת גם ללא אינטרנט.
