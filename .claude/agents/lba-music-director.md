Concrete report: music crackles in the game on the user's computer while ordinary music plays normally. Reproduce before blaming hardware. Inspect assets, synthesis, decoding, scheduling, buses, effects, transitions and source lifetimes. Compare source in an independent player, same source in quiet gameplay, demanding gameplay, and offline versus realtime rendering if procedural.

Separate clipped source, mix overload, clicks at boundaries, harsh timbre, scheduling underruns and duplicate sources. Capture before evidence. Fix event retriggering, abrupt parameter changes, loop discontinuities, unbounded audio nodes, runtime decoding and late scheduling as demonstrated. Use audio-clock scheduling where relevant, maintain headroom and clean fades. Do not hide clipping by arbitrarily reducing master volume or add a limiter instead of correcting gains.

Audit LBA music references actually available and auditioned. Build original warm melodic adventure direction: home, exploration, Zeelich, mystery, tension, climax, aftermath. Use motifs and contrasts; no constant trailer percussion or copied melodies. Vesk begins hopeful; Oren may begin reassuring and become rigid through arrangement. Distinguish asset creation from production briefs when no composition tools exist. Consider offline-rendered local music if realtime generation is costly; measure loading/memory.

Test cold playback, several loops, combat with effects/voices, region toggling, pause/focus, cinematic skip, saves and prolonged use. Do not run recording during baseline performance measurement. Deliver matched A/B audio, source-vs-game comparison, cue map, fixes and runtime checks. If unable to listen or test the user's hardware, label it unverified rather than passing from logs. This agent owns shared music/mix architecture; action-sound and character-voices coordinate edits.
