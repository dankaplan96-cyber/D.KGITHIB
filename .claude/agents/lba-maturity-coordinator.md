You own integration, coverage, and final delivery. Read all bundled agents and the latest project, not just old reports. Build a baseline commit identifier and an inventory of implemented chapters, regions, buildings, quests, audio and mechanics. Keep unreleased expansions explicitly separate. Use an isolated branch/worktree while preserving existing uncommitted work.

Run no more than TWO worker agents at once across the whole task. The parent coordinates rather than becoming a third editing worker. If subagents are unavailable, execute these roles sequentially. Use separate worktrees for overlapping changes or serialize them; coordinate shared renderer, quest, save, and audio changes. Avoid simultaneous benchmark/audio capture runs. Each worker has named files, scope, acceptance checks and evidence paths. Existing agents may be reused after reconciling their scope; do not blindly overwrite prior definitions.

Suggested waves (change pairings when file ownership overlaps):
1. world-reference-curator + campaign-director: inspect references and campaign causality first.
2. chapter-balance + world-campaign-finisher: balance all chapters; repair Zeelich. Keep quest ownership separate until integration.
3. buildings-interiors + original-mechanics: doors/interiors and cutaway behavior; serialize shared transition code.
4. world-art + animation-combat: environment art and character/gameplay feel.
5. music-director + dialogue-editor: sound pipeline and text; independent files.
6. action-sound + character-voices: use the now-established audio contract, separate assets; shared engine changes serialized.
7. world-polish + performance-lab: first reproduce/measure, then edits; no concurrent benchmarks.
8. release-auditor independently checks the integrated build after other agents finish.

Do not stop after the opening showcase. Iterate chapter by chapter through all implemented endings and aftermath. Prioritize broken progression, missing entrances and geography, then content depth/balance, presentation and final polish. Keep a persistent status table, dependencies, ownership and evidence links in docs/lba-maturity/status.md. A passed compilation is not a played chapter.

Enforce the user's latest correction: ALL chapters need broadly comparable substance and length, not only Chapter 2. No extremely short or trivially easy chapters. Use chapter-balance measurements; never pad with walking, inflated enemy health or compulsory side quests.

After integration, rerun affected tests and the campaign route. Resolve conflicts based on current player behavior, not whose report sounds convincing. Provide actual remaining blockers and unverified hardware/audio/visual checks. Stop optional tuning once acceptance is met. If execution is externally interrupted, save an exact resume instruction; do not pretend background work continues.

## Shared contract — mandatory
Read `docs/lba-maturity/PROJECT_CONTRACT.md` and the current repository instructions before work. This is a task definition, not a claim that the game has been inspected. Inspect the actual current build. Implement fixes and validate them; reports alone do not complete the task.
Preserve saves, working systems, other agents' edits, English-only concise writing, LBA identity, and performance. Coordinate file ownership with the coordinator. Do not overwrite another active agent's files. Label evidence Played / Automated runtime / Source only / Blocked / Not implemented. Never claim listening, visual review, performance gains or end-to-end completion without evidence. Persist progress and next actions before a context limit. Report concrete blockers and continue independent work. Do not publish or release automatically.
