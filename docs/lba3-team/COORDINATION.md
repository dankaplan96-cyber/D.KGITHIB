# Additional LBA3 specialists

## Main-session responsibility

The main Claude Code conversation coordinates these six agents and any installed earlier developer, character artist, animator, graphics, polish, and review agents. These files do not start a service or supply source assets. Use actual available tools, project permissions, and resource limits. Do not bypass approvals, purchase services, publish builds, or assume access to another session's files.

Inspect the current repository and instructions first. Preserve existing work, saves, and newer approved decisions. Find the user's supplied LBA source/data and current reference pack. Missing data must be identified precisely, not replaced with invented provenance. Stabilize blocking regressions before expanding content.

Assign exact owned paths for every task. Only one writer edits a shared file at a time. Use agreed small interfaces for equipment, motion, and UI. Do not install parallel competing managers, controllers, quest engines, or backlog documents. Reuse existing STATE/BACKLOG/QA files and preserve agent definitions with different names.

## Practical order

1. Baseline: run current build, identify current problems and source-data availability; inventory installed agents and tools.
2. Import one original character end-to-end if data is present. In parallel only for disjoint read-only work, inspect narrative, screen clarity, and movement.
3. Repair high-impact locomotion/UI issues. Coordinate mesh/rig and animation compatibility before scaling imports.
4. Implement and test one complete jetpack use case with acquisition and save/recovery. Verify story boundaries before enabling it throughout the world.
5. Implement one deeper playable story sequence and its consequences. Consider at most two additional fitting equipment concepts; do not manufacture a large arsenal.
6. Apply copy cleanup and interface polish to changed journeys; perform integration review and regression checks. Then select the next concrete task.

Tasks contain ID, scope, paths, dependency, user-visible result, acceptance criteria, and verification. States: TODO / IN_PROGRESS / REVIEW / DONE / BLOCKED. Completion requires implementation plus evidence, not a plan or code that merely compiles.

Use an installed reviewer for independent verification. If unavailable, perform an explicit review in the main session and identify it honestly as self-review. Do not claim separate agents ran when subagent support is unavailable. Avoid recursive delegation.

## Evidence and guardrails

Keep user-facing text English-only and natural. Preserve LBA's warmth, weirdness, humour, readable visual style, and established twelve-year continuation. Distinguish canon from new sequel invention. Use actual references; no invented claim that an original asset was extracted or original animation measured.

For every change test the affected normal player journey and meaningful interruption cases: pause, repeated input, transition, dialogue, death, and save/reload. Debug shortcuts may isolate failures but do not prove normal progression. Keep test saves isolated. Protect essential clues during cleanup.

Visual work needs runtime views; motion needs playback; performance needs declared hardware/renderer/settings, comparable scenes, warmup, and frame-time measurements. Software rendering does not certify GPU performance. Use current project targets and record measurable costs of new models, flight effects, and UI updates.

Store concise evidence in the project's QA location and update persistent state with revision, finished work, blockers, and next exact step. At context/usage limits checkpoint; the kit cannot run after the session closes. Continue authorized unblocked tasks without asking the user to repeatedly say continue, but do not loop endlessly or silently waive blocked acceptance criteria.

Final handoff: changes, checks, build, remaining issues, and next task. Full-game readiness and playtime require actual end-to-end evidence, not the number of agents or files.
