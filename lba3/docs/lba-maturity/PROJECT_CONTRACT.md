# LBA3 Maturity Pack — shared project contract

This package is a set of Claude Code agent instructions, not executable desktop bots and not evidence that the game has been inspected. Integrate with the actual repository before running. Do not replace the repository's AGENTS.md or CLAUDE.md.

## Latest user priorities
- Finish the entire existing game. Chapter 3 Zeelich was observed as lifeless, poorly matched to LBA2, with missing doors and bugs.
- ALL chapters must be broadly comparable in active length and substance; none extremely short or trivially easy. This supersedes an earlier focus on Chapter 2 alone. Use measured playtime, clearly labeled first-play estimates and a provisional 75–125% band around the agreed core-chapter target. Avoid filler; allow a justified prologue/aftermath.
- Accessible buildings should have real entrances and usable, appropriate interiors. Explicit distant scenery and story locks must be distinguished, never used to conceal unfinished work.
- Preserve characteristic mechanics, particularly entering buildings and roof/wall cutaways. Visibility changes must not remove physical collisions.
- Aim for a documented editorial resemblance score of at least 85/100 for each revisited original location. This is a rubric, not an objective percentage of identical pixels. Missing evidence means unverified. New worlds have no invented original counterpart.
- Fix music crackle; normal music plays cleanly on the player's machine. Give actions meaningful sounds. Character speech remains pleasant gibberish with English subtitles.
- Preserve performance, saves, working systems, coherent story and concise English UI.

## Evidence and workflow
Read current source/story/assets before editing. Original LBA reference evidence outranks fan reconstructions for original geography; the established sequel story determines justified twelve-year changes. Record sources/provenance and distinguish original canon from our inventions. Do not invent missing reference details or unavailable tool capabilities.
Work in at most two worker agents at a time; coordinate shared file ownership, integrate and verify between waves. Do not run expensive tests concurrently. No automatic publishing, account changes or external communication. Respect existing tool permissions.
Actual fixes and complete player routes matter more than reports. Preserve source IDs and quest/save compatibility. No wholesale rewrite, new planets, unrelated features or extra lore to mask incomplete content. Oren expansion remains scoped to its current implementation/release gate.
Store persistent coverage, decisions, reproduction steps and evidence paths in docs/lba-maturity. Status: Verified in play / Automated runtime only / Source-reviewed only / Implemented unverified / Blocked / Not implemented. Keep exact build/commit and settings for evidence. Do not call unit tests a full playthrough or logs a listening test.

## Acceptance across disciplines
Each chapter: clear purpose, substantial varied gameplay, fair challenge, discoveries, consequences, safe retries, compatible save/load and a reachable next chapter.
Each region: recognizable identity, useful paths, entered/exited buildings, grounded props/NPCs, inhabited context, reasonable loading and measured performance.
Each audio system: source provenance, correct event timing, source cleanup, volume controls, unclipped comfortable mix, auditioned samples or explicit listening blocker.
If access/hardware/context limits prevent completion, save exact completed and pending tasks and resume command. Never promise unattended background continuation after the session ends.
